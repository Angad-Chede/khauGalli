1. Executive Summary & Vision

KhauGalli (Codename: Tiffin) is a production-grade, 4-role food ordering and delivery marketplace built specifically for hyper-local Indian street food, tiffin centers, and culinary clusters.

The platform completely rejects brittle shortcuts: all monetary amounts are modeled strictly in integer paise, geolocation is natively evaluated inside PostGIS via GIST indexes, orders follow pure mathematical state machines with append-only event audits, and asynchronous worker tasks are decoupled through the Transactional Outbox Pattern.

Zero-Compromise Backend Tenets:
  • Integer Paise Math: Absolute ban on floating point arithmetic for prices, GST, delivery, and refunds.
  • PostGIS Spatial Discovery: Native ST_DWithin and ST_Contains queries.
  • Cryptographic Webhooks: Raw body buffer preservation with constant-time HMAC-SHA256 signature checks.

2. Detailed Walkthrough of Completed Phases

Phase 0: Foundations, Infrastructure & Auth Guardrails

  • Monorepo Topology: Configured using pnpm workspaces and Turborepo (apps/api, apps/web, apps/worker, packages/db, packages/shared).
  • Zod Environment Validation: packages/shared/src/env.ts enforces strict runtime checks and crashes on boot in production if demo flags or unhashed credentials are used.
  • Cryptographic OTP Auth: 6-digit random code, SHA-256 hashed in Redis, 5-minute TTL, rate limited to 3 attempts. Fixed demo code (123456) is strictly restricted to the 4 seeded demo phones and blocked in production.
  • Demo Persona Switcher: Floating bar enables instant persona switching. Unlike fake mock switches, clicking a persona executes real OTP authentication under the hood.
  • Idempotent Seed Engine: packages/db/src/seed.ts marks seeded users as is_demo: true with safe numbers (+919999900001–0004) so notification adapters never message real people.

Phase 1: Catalog & Customer Browse

  • Pure Pricing Package (@tiffin/shared/pricing): Features text-based rupee parser (parseRupeesToPaise), delivery fee algorithm (base ₹30.00 for 2 km + ₹10.00/started km, capped at ₹150.00), 5% food GST, and 15-minute immutable quote generation (calculateCartQuote). Verified across 1,000 property-based runs via fast-check.
  • PostGIS Spatial Discovery (GET /restaurants): PostGIS ST_DWithin and ST_Distance queries calculate geodesic distance from customer coordinates, verify service zone polygon containment, evaluate Asia/Kolkata operating hours, and calculate dynamic ETAs.
  • Multi-Tier Search (GET /restaurants/search): Uses prefix matching (< 4 chars) combined with Postgres Full-Text Search (tsvector with simple dictionary) and Trigram similarity (word_similarity) for typo tolerance (e.g. "briyani" matches "Biryani Darbar").
  • Redis Cart & Multi-Restaurant Conflict: Ephemeral Redis cart strictly enforces the single-restaurant invariant (HTTP 409 RESTAURANT_CONFLICT). Validates modifier group min/max selection constraints.
  • IDOR-Protected Restaurant Portal (/r/*): Restaurant ID is derived server-side from the restaurant_staff table using req.user.sub. Staff can toggle operational status and instant 86-availability, bumping menu_version.

Phase 2: Orders, Payments & Kitchen KDS

  • Order State Machine (packages/shared/src/state-machine.ts): Enforces deterministic transitions (CREATED → PAYMENT_PENDING → PLACED → ACCEPTED → PREPARING → READY → PICKED_UP → DELIVERED) and terminal exits (PAYMENT_FAILED, REJECTED_BY_RESTAURANT, EXPIRED, CANCELLED). Prevents illegal jumps.
  • Idempotent Placement (POST /orders): Enforces Idempotency-Key header. Retried requests return the existing order with isReplay: true and zero duplicate DB rows.
  • Price Shift Detection (HTTP 409 PRICE_CHANGED): Re-verifies live prices and taxes against PostgreSQL. If prices shifted or quote is older than 15 minutes, aborts with HTTP 409 returning the refreshed quote.
  • Raw Body Webhook Engine (POST /webhooks/razorpay): Uses custom Fastify content-type parser to preserve unaltered raw buffers. Performs timing-safe HMAC-SHA256 verification, deduplicates events via webhook_events, and prevents out-of-order state regression (captured payment cannot be downgraded to authorized).
  • Auto-Expiration Engine: 3-minute kitchen acceptance window. Unaccepted orders in PLACED auto-transition to EXPIRED and trigger full refunds.
  • Transactional Outbox Relay Worker (apps/worker): Background daemon uses SELECT ... FOR UPDATE SKIP LOCKED on outbox_events to publish events to Redis Pub/Sub channels (restaurant:{id}:orders, order:{id}:updates).
  • Live Kitchen Display System (KDS): 3-column Kanban board in /restaurant with Web Audio alert chime, live 3-minute countdown timers, and touch-friendly accept/reject/ready controls.
  • Live Order Tracker: Customer tracking page (/customer/orders/:id) with 5-stage visual progress stepper, cancellation trigger, and real-time polling.

5. Remaining Manual Setup & Operational Checklist

To run the complete platform locally or deploy to staging, follow this clear operational checklist:

Operational Prerequisites: The application code, builds, migrations, and test suites are 100% complete. Running the live interactive servers requires the following local external dependencies to be turned on.
  1. Start Local Infrastructure (Docker Compose):

    Ensure Docker Desktop is open and running on your machine, then execute in PowerShell:

    docker compose up -d
    This spins up the postgis/postgis:16-3.4 container on port 5432 and redis:7-alpine on port 6379.
  2. Set Up Environment File:

    Ensure a .env file exists in the repository root. Copy from .env.example:

    Copy-Item .env.example .env
    Pre-configured for local development (DATABASE_URL, REDIS_URL, JWT_SECRET, and mock Razorpay credentials).
  3. Apply Database Migrations:

    Once Docker PostGIS is accepting connections, run the Drizzle migration runner:

    pnpm db:migrate
    Applies 0000_lonely_doomsday.sql, 0001_phase1_catalog_enhancements.sql, and 0002_phase2_orders_payments.sql.
  4. Seed Demo Data:

    Populate the demo personas, restaurants, service zones, and menus:

    pnpm db:seed
  5. Launch All Services:

    Start the monorepo dev processes simultaneously using Turborepo:

    pnpm dev
    • Customer & Restaurant Web UI: http://localhost:3000
    • Fastify REST API: http://localhost:4000
    • Swagger API Documentation: http://localhost:4000/docs
    • Background Outbox Worker: Automatically starts in background.
